Prompt/dataset source (from `e2e-bench-runner/impl/run_bench.py`):
- `make_prompts(n, words=200, seed=2026)`: each prompt = **200 random words** drawn (with fixed
  `random.Random(2026)`) from a fixed 40-word vocabulary `WORDS` (deterministic, reproducible).
- **Input length is 200 WORDS** (NOT inferred from column name). Tokenized length ≈ 200 tokens
  (word≈token for this vocab); the rerun uses the identical `make_prompts` so input distribution
  is bit-identical to the original.
- Request payload: POST `/generate` `{"text": prompt, "sampling_params": {"max_new_tokens": max_new,
  "temperature": 0.0, "ignore_eos": True}}`. `ignore_eos=True` ⇒ every request emits exactly `max_new`
  tokens (fixed output length).
- Arrival pattern: **closed-loop** — all `num_prompts` requests submitted to a
  `ThreadPoolExecutor(max_workers=concurrency)`. Since `num_prompts == concurrency`, all requests are
  in flight at once (a single burst wave). NOT a Poisson/rate arrival.
- Repeats: harness ran `num_runs_total=3`, dropped run 0 as warmup, used runs 1–2 (median).
- Seed: 2026 (identical prompts across all configs/models).

## 6. The one deliberate change: streaming client to obtain TTFT

The original client is **non-streaming** and therefore cannot report TTFT. The rerun uses a
**streaming** `/generate` client (`scripts/v51_stream_bench.py`) that:
- reuses the **identical** `make_prompts(seed=2026, words=200)`, `num_prompts`, `concurrency`,
  `max_new`, `temperature=0`, `ignore_eos=True`, and closed-loop `ThreadPoolExecutor(concurrency)`;
- adds `"stream": True` and records, per request: TTFT (submit → first token), per-chunk
  inter-arrival (ITL), TPOT (mean ITL), E2E (submit → last), output_tokens.
- **Client-observed TTFT includes admission/scheduler queueing** (intended — that is the
  user-visible effect of `max_running_requests`).

This changes only the transport (stream on/off); the workload, payload, seed, and concurrency model
are identical to the original.
